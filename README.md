# Entity-centric evaluation of large language model responses for medical question-answering tasks — Data and Code Repository

This repository contains the data and code accompanying the paper:
> **Entity-centric evaluation of large language model responses for medical question-answering tasks**
> [Yi Liu, Vijaya B. Kolachalama].[2026]. 

## Overview

This study evaluates the responses generated by several **Qwen 2.5** models on
medical question-answering benchmarks. We introduce **EntQA**,  a reference-free, entity-centric metric that evaluates how well  a reference-free, entity-centric metric that evaluates how well LLM-generated responses retain clinically relevant biomedical concepts from patient backgrounds and diagnostic questions, and compare it against a set of baseline
metrics by analyzing how each metric correlates with (i) answer accuracy at the group level and case level, and (ii) model size.

## Directory structure

```
QA_pipeline/
├── Benchmark/            Raw benchmark data (MedQA, MedExpQA, USMLE Step 1,2,3)
├── Benchmark_processed/  Cleaned / preprocessed benchmark data used as model input
├── processed_data/       Responses generated by the different Qwen 2.5 models on the
│                         benchmarks — i.e. the model outputs analyzed in this study
├── Results/              Evaluation scores: our proposed metric and all baseline
│                         metrics applied to the generated responses
├── Paper_writing/        Statistical analyses reported in the Results section of the paper
    ├── processed_data/         Intermediate data prepared for these analyses
│   ├── accuracy_alignment/     Spearman, Kendall correlation between the metrics and answer accuracy (at group level)
│   ├── accuracy_alignment_case_level/.  Point-biserial correlation between the metrics and answer accuracy (at case level)
│   └── Model_size_exploration/  Correlation between the metrics and model size
├── supplement_info/      Additional evaluation results from running the pipeline under
│                         different parameter settings, plus the corresponding statistical
│                         results (robustness / sensitivity analyses)
├── utils/                Core code: computing the proposed metric and the baseline on model responses
├── utils_vis/            Correlations analysis code:  between the metrics and answer accuracy and model size        
└── README.md
```

## How the pieces fit together

1. `Benchmark/` → preprocessed into `Benchmark_processed/`.
2. The Qwen 2.5 models are run on the processed benchmarks to produce the responses
   in `processed_data/` (code in `utils/`).
3. The proposed metric and baseline metrics are computed on those responses; scores
   are stored in `Results/`.
4. The statistical analyses linking metric scores to accuracy and model size are in
   `Paper_writing/` and correspond to the figures/tables in the paper.
5. `supplement_info/` contains parameter-variation experiments and their statistics.

## Reproducing the results

The overall workflow is driven by utils/main.py — reading it gives the end-to-end
pipeline (how the proposed metric and baseline metrics are computed on the responses,
and how their outputs feed the analyses). The statistical analyses (correlations with
accuracy at group/case level and with model size) are in utils_vis/. To reproduce
the reported results, start from utils/main.py for the metric evaluation, then run
the analysis scripts in utils_vis/.
**Note on reproducibility**: the responses in processed_data/ were produced with
specific Qwen 2.5 model versions and generation settings. Because LLM generation is
stochastic, re-running generation will not necessarily reproduce identical outputs.
To replicate the reported findings exactly, use the generated data provided here
rather than regenerating it.
